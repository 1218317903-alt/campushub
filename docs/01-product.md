# 01 · 产品定位、用户与范围

> 对应要求：1 产品定位 · 2 核心用户 · 3 典型使用场景 · 4 用户主流程 · 5 页面信息架构 · 6 MVP 范围

---

## 1. 产品定位

### 1.1 一句话定位

**CampusHub AI 是一个"知识空间 + 内容社区 + 信息聚合"三合一的高校学习平台：用户在这里保存自己的资料，用 AI 理解它们，把值得分享的部分传播出去，并从平台持续采集的公开信息流中发现新东西。**

### 1.2 定位坐标系

平台不是一个点，而是三段式的价值链条，每一段都能独立成立：

```
私域（价值沉淀）        公共（价值连接）          外部（价值输入）
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│  Workspace   │ ───► │  Community   │ ◄─── │   Discover   │
│ 资料 / 笔记   │ 发布  │ 帖 / 讨论     │ 引用  │ 资源 / 动态   │
│ AI 问答 / RAG │      │ 评论 / 热榜   │      │ 采集 / 摘要   │
└──────────────┘      └──────────────┘      └──────────────┘
        ▲                                          │
        └──────────────  AI Platform  ─────────────┘
              （检索 / 总结 / 引用 / Agent 贯穿三域）
```

**关键设计判断：**

- **私域是入口，不是终点。** 用户因为"我的资料能被我自己的 AI 读懂"而留下，因为"我的东西能被别人看到"而活跃。
- **公共域是留存引擎。** 私域是低频的（写作业才来），公共域是高频的（每天刷一刷）。没有 Discover/Community，DAU 会归零。
- **Discover 是内容供给侧。** 冷启动没有 UGC，Discover 用公开数据把"内容生态感"撑起来。
- **AI 是横切能力**，不做成独立的第五个域。

### 1.3 明确不做（定位边界）

| 不做 | 原因 |
|---|---|
| 刷题 / 面试题库 / 八股 | 你已明确排除；且这是一个红海赛道，与"内容生态"叙事冲突 |
| 通用聊天机器人 | 没有领域与上下文优势，用户凭什么用你的而不是原生 App |
| 校园社交 / 交友 / 树洞 | 内容审核与合规风险陡增，且不服务于"学习"主线 |
| 课程管理（教务对接 / 课表） | 需要与校内系统对接，个人项目无法覆盖 |
| 网盘 | 存储成本与合规压力，且价值被大厂覆盖 |
| 完整在线 IDE / 代码运行 | 沙箱隔离成本极高，一旦做不好就是安全问题 |

## 2. 核心用户

不用"大学生"这种粗粒度画像。定义 5 个有行为差异的角色：

### P1 · 低年级学习者（大一/大二）
- **目标**：跟上课程、找资料、别掉队
- **行为**：搜索课程关键词、下载/收藏资料、提问
- **痛点**：不知道什么资料好；找不到同课程的人
- **价值主张**：课程 Workspace 模板 + 优质资源聚合 + 同学讨论

### P2 · 技术学习者 / 自学者
- **目标**：系统学习某个技术栈，形成自己的知识库
- **行为**：建 Workspace、写 Markdown 笔记、上传 PDF、用 AI 提问、关注技术话题
- **痛点**：笔记散落各处；学过的 AI 记不住；重复查同样的东西
- **价值主张**：可被 AI 检索的个人知识库 + 引用可追溯的问答

### P3 · 项目 / 竞赛团队成员（数学建模、大创、毕设、CTF、ACM）
- **目标**：团队共享资料、推进任务、不重复劳动
- **行为**：建团队 Workspace、邀请成员、上传文档、分配 TODO、阶段总结发布
- **痛点**：微信群 + 网盘 + 共享文档三处割裂；经验无法沉淀
- **价值主张**：团队知识库 + 权限控制 + 项目复盘一键发布到社区
- **★ 这个角色是 Workspace 域的核心验证者，也是协作功能的真实需求来源**

### P4 · 求职 / 实习阶段学生
- **目标**：拿 offer、了解岗位与行业
- **行为**：看实习/招聘公开信息、看面经与项目经验帖、收藏、关注趋势
- **痛点**：信息散、时效性差、真假难辨
- **价值主张**：Discover 的招聘信息聚合 + 社区真实经验帖（带来源）

### P5 · 内容贡献者 / 社区活跃者
- **目标**：表达、被认可、建立个人品牌
- **行为**：发帖、回答、整理资源清单、举报垃圾内容
- **痛点**：写的东西没人看；平台不尊重原创
- **价值主张**：热榜曝光 + 个人主页作品集 + **内容来源与署名体系**

### 辅助角色
- **访客（未登录）**：只能看公开内容，用于降低内容消费门槛与 SEO
- **运营/管理员**：平台方，管理内容、审核、数据源、系统监控

## 3. 典型使用场景

写成"用户故事 + 系统行为"的形式，便于直接转化为验收标准。

| # | 场景 | 用户动作 | 系统行为 | 涉及域 |
|---|---|---|---|---|
| S1 | **期末复习建课程库** | 建 Workspace「数据结构期末」，上传 3 份 PDF + 2 份课件，让 AI 总结考点 | 异步解析→切片→向量化→AI 基于该 Workspace 回答并给引用 | Workspace + AI |
| S2 | **数学建模组队备赛** | 建团队 Workspace，邀请 2 人，上传历年优秀论文，建 TODO | 成员权限校验；任务看板；文档可被全组 AI 检索 | Workspace |
| S3 | **把毕设成果发到社区** | 在 Workspace 里点「发布到社区」，二次确认可见范围 | 生成社区帖子（含图片/Markdown），**不包含私有文件原文**，用户可预览 | Workspace → Community |
| S4 | **搜一个技术主题** | 搜索「Spring AI」 | 一次返回：社区帖 / 公开资源 / 开源项目 / 我参与的 Workspace 文档，分组展示、标明来源 | Search |
| S5 | **追技术动态** | 打开 Discover，切到「Java」话题 | 看到近期采集的官方博客、GitHub 新项目、社区讨论，按时间与热度混合排序 | Discover |
| S6 | **提问研究型问题** | 「最近值得关注的 Java AI 项目有哪些？」 | Research Agent 多源检索→时间过滤→重排→总结→逐条给引用 | AI + Discover + Search |
| S7 | **每日速览** | 早上打开首页 | 看到平台根据昨日新采集内容生成的 Topic Digest（AI / Open Source / 校园 / 竞赛） | Discover + AI |
| S8 | **讨论与互动** | 在别人帖子下评论，点赞 | 异步写通知，作者通过 SSE 实时收到；热榜随互动更新 | Community + Notification |
| S9 | **举报垃圾内容** | 举报一条广告帖 | 进入审核队列，达到阈值自动折叠，管理员复核 | Moderation |
| S10 | **管理员巡检** | 打开 Admin Console | 看到采集成功率、MQ 积压、缓存命中率、Token 消耗、失败任务 | Admin |

## 4. 用户主流程

### 4.1 核心闭环（North Star 路径）

```
发现 → 消费 → 沉淀 → 生产 → 反馈 → 再发现
```

具体化为事件序列：

```
Landing（未登录可浏览 Trending）
  ↓ 注册/登录
Home Feed（推荐 + 热榜 + Digest）
  ↓ 点击兴趣话题
Discover / Community 浏览
  ↓ 搜索
统一搜索结果（跨来源分组）
  ↓ 内容有价值 → 沉淀
创建 Workspace → 上传文档 / 写笔记
  ↓ 异步处理完成（进度可见）
AI 基于我的文档问答（带引用）
  ↓ 产生新的理解 → 外化
发布到 Community（显式确认）
  ↓ 他人互动
评论 / 点赞 → 通知 → 回访
  ↓
主页推荐因行为变化（可解释）
```

**北极星指标建议**：`周活跃「有知识沉淀行为」的用户数`（即一周内至少创建/上传过一次 Workspace 内容的用户）。
**护栏指标**：举报率、AI 引用异常率、采集失败率。

### 4.2 主流程中的"失败可能性"（必须在设计里兜住）

| 环节 | 可能失败 | 设计对策 |
|---|---|---|
| 注册 | 邮箱验证码收不到 | 支持跳过验证直接体验（限制发文权限） |
| 浏览 | 首页为空 | Bootstrap 种子数据保证非空（V0 硬要求） |
| 搜索 | 无结果 | 空结果页推荐相关标签 + 热门内容，而不是白屏 |
| 上传 | 解析慢/失败 | 进度可见、失败可重试、可删除、错误原因明确 |
| AI | LLM 超时/超额度 | 降级到"仅检索不生成"，返回检索结果列表 + 提示 |
| 发布 | 误把私有内容公开 | 二次确认 + 预览 + 默认仅自己可见 + 撤回窗口 |
| 通知 | 推送丢失 | SSE 断线重连 + 未读数 Redis 计数兜底 + 站内通知列表 |

## 5. 页面信息架构

### 5.1 站点地图

```
CampusHub AI
├─ /                        首页（个性化 Feed：Trending / 推荐 / Digest / 新内容）
├─ /discover                发现
│   ├─ /discover/topic/:slug      话题页（AI / Java / 开源 / 竞赛 / 求职…）
│   └─ /discover/source/:id       数据源页（该来源的条目 + 来源信息）
├─ /community               社区
│   ├─ /community/c/:category     分类
│   ├─ /community/tag/:tag        标签
│   ├─ /community/hot             热榜
│   ├─ /community/p/:id           帖子详情（正文 + 评论树）
│   └─ /community/new             发帖（Markdown 编辑器 + 预览）
├─ /search                  统一搜索（多来源分组 + 筛选器）
├─ /u/:username             用户主页（作品 / 收藏（权限受控）/ 简介）
├─ /workspace               我的空间列表
│   ├─ /workspace/:id             空间首页（概览 + 最近文档 + 任务）
│   ├─ /workspace/:id/docs        文档库（上传、解析状态、标签、搜索）
│   ├─ /workspace/:id/notes       笔记（Markdown）
│   ├─ /workspace/:id/ai          AI 问答（RAG + 引用）
│   ├─ /workspace/:id/tasks       TODO
│   ├─ /workspace/:id/members     成员与权限
│   └─ /workspace/:id/settings    设置（可见性、归档、删除）
├─ /notifications           通知中心（全部 / 未读 / 提及 / 系统）
├─ /ai                      全局 AI（公共知识问答 / Research）
├─ /admin                   后台（仅 ADMIN）
│   ├─ /admin/dashboard           指标总览
│   ├─ /admin/users /workspaces /community
│   ├─ /admin/moderation          审核队列
│   ├─ /admin/sources             数据源管理
│   ├─ /admin/crawler             采集任务与失败
│   ├─ /admin/search              索引状态与重建
│   ├─ /admin/ai                  模型配置 / Token 用量 / 评测
│   └─ /admin/audit               审计日志
└─ /settings                个人设置（资料 / 兴趣标签 / 通知偏好 / 安全）
```

### 5.2 首页模块优先级（第一眼必须"有生态感"）

按视觉权重从上到下：

| 位置 | 模块 | 数据来源 | 为空时的兜底 |
|---|---|---|---|
| 顶部 | 搜索框 + 快捷话题 chips | 标签字典 | 固定展示 8 个核心标签 |
| 第 1 屏左 | **Trending**（社区热榜 Top 6） | 热榜 ZSet | Bootstrap 种子帖 |
| 第 1 屏右 | **Topic Digest**（今日 AI 速览卡） | Digest 服务 | Bootstrap 预生成的 Digest |
| 第 2 屏 | **Recommended For You**（带推荐理由） | 推荐服务 | 热度 + 时间衰减 |
| 第 3 屏 | **开源项目推荐**（GitHub 采集） | Discover | Bootstrap 种子项目 |
| 第 3 屏 | **学习资源**（公开资源） | Discover | Bootstrap 种子资源 |
| 第 4 屏 | **社区最新讨论** | Community | 种子帖 |
| 右侧栏 | 数据源状态小卡（"已接入 12 个公开来源"） | Provenance 统计 | 固定文案 |

> 设计原则：**首页没有任何一个模块允许出现空白状态**。这不是"以后补"，是 V0 的验收项。

### 5.3 关键页面的信息层级（以帖子详情为例）

```
标题 / 作者 / 发布时间 / 标签 / 来源标注（若引用外部内容）
正文（Markdown 渲染，图片懒加载）
── 互动栏：点赞 · 收藏 · 评论 · 分享 · 举报
── AI 辅助区：「让 AI 总结这篇讨论」+「相关问题」（可折叠，不抢主体）
── 评论区（2 层树，超出折叠）
── 相关推荐（同标签 + 向量相似）
```

## 6. MVP 范围

### 6.1 MoSCoW 分级

**Must have（V0+V1 必须完成，缺任一则产品不成立）**

| 域 | 条目 |
|---|---|
| Identity | 注册 / 登录 / 登出 / 刷新 Token / 个人资料 / 兴趣标签 |
| Community | 发帖（Markdown）/ 图片上传 / 评论 / 点赞 / 收藏 / 浏览计数 / 分类 / 标签 / 首页 Feed / 热榜 |
| Workspace | 创建 / 邀请成员 / 角色 / 上传文档 / 异步解析 / 笔记 / 文档列表与搜索 / 删除 |
| Discover | 数据源配置 / RSS+API 采集 / 去重 / Provenance / 列表页 / 话题页 |
| Search | 统一搜索（多来源分组）/ 标签筛选 / 权限过滤 |
| AI | Workspace RAG 问答 + 引用；公共知识问答（带引用）；AI 总结 |
| Notification | 点赞 / 评论 / 回复 / 邀请 / 系统消息；未读数；站内列表 |
| Moderation | 举报 / 敏感词 / 管理员审核队列 / 折叠 |
| Admin | Dashboard 指标 / 用户列表 / 内容管理 / 数据源与任务 / 审计日志 |
| Bootstrap | 种子数据 + 索引预热 + 一键初始化 |

**Should have（V2-V3）**
关注关系（话题级）、推荐升级（协同信号）、Digest 全自动生成、Elasticsearch 全文检索替换兜底、缓存与限流、SSE 实时推送、压测与优化、OSS 签名直传、内容版本历史。

**Could have（V4-V5）**
Agent 编排、MCP 工具暴露、Hybrid Rerank 模型、AI 评测回归、故障演练剧本、多租户配额、开放 API。

**Won't have（本阶段明确不做）**
协同编辑（OT/CRDT）、私信、直播、付费、小程序端、代码沙箱、通用网页爬虫、深度学习推荐、K8s 集群编排。

### 6.2 MVP 的"三条必须闭环的主线"

1. **内容闭环**：有人发 → 有人看 → 有人互动 → 有通知
2. **知识闭环**：上传 → 解析 → 可问 → 有引用 → 可发布
3. **数据闭环**：采集 → 去重 → 入库 → 可搜 → 可展示来源

> 三条闭环各容忍"部分功能缺失"，但**不允许断路**。例如：V0 可以没有 AI，但必须能上传并看到解析状态；可以没有向量检索，但必须有来源信息。

### 6.3 明确的取舍：V0 不做 AI

理由：
- AI 的价值依赖"有内容可检索、有权限可校验"，这两件事都在 V0 建设。
- V0 的目标是"启动即有内容的可演示产品"，AI 是 V1 的增量。
- 把 AI 放在 V0 会稀释精力，导致"AI 能聊天但社区是空的"——正是你最想避免的状态。
